# BoxFox Router v1 integration contract

Runtime: Node 24 ESM; HTTP on 127.0.0.1:3101 in development. All frontend traffic is same-origin via Vite proxy. Production serves the built frontend on 3100. Provider types are in `frontend/src/types/provider.ts`.

Admin requests use `Content-Type: application/json` for writes and `X-BoxFox-Admin: 1`. Server checks exact allowed Origin + Host for browser calls and rejects cross-origin/admin calls without this header. Only loopback deployment is supported. External `/v1` endpoints require a generated client Bearer key; internal generation uses admin checks. `/api/router/health` is public read-only.

Responses: JSON objects; errors `{error:{code,message,retryable}}` with safe messages. GET `/api/router/state` returns ProviderSnapshot. GET `/api/router/providers`, GET `/api/router/providers/:id`, and PUT `/api/router/providers/:id` body `{roundRobin?,connectionOrder?}` expose catalog/detail and account selection policy. GET `/api/router/connections`, POST `/api/router/connections` body `{providerId,name,apiKey?,endpoint?,projectId?}`, PATCH `/api/router/connections/:id` body `{name?,apiKey?,endpoint?,projectId?,enabled?,autoSync?,enabledModelIds?}`, DELETE same URL disconnects/deletes binding. POST `/:id/test` discovers models; POST `/:id/models/refresh`; POST `/:id/models/:modelId/test` performs real inference; GET `/:id/quota` refreshes quota.

OAuth: POST `/api/router/oauth/attempts` body `{connectionId}` => OAuthAttempt. GET `/api/router/oauth/attempts/:id` polls; DELETE cancels. Authorization URL opens in browser. Dedicated temporary loopback callback listener uses the embedded-client compatible `/oauth-callback` on port 51121 by default (configurable); complete state verified on server. Tokens never reach frontend. Failed bootstrap retains credential but sets project state required/failed so it is repairable.

Routing: POST `/api/router/aliases` body `{name,strategy,targets,enabled?}`; PATCH/DELETE `/api/router/aliases/:id`. PUT `/api/router/default` body ProviderDefault. Targets use saved connection IDs and real model IDs. GET `/api/router/keys`, POST body `{name,allowedModels?}` returns `{key,record}` (raw key once); DELETE `/api/router/keys/:id` revokes. GET `/api/router/usage` => RouterUsage[]. For allowedModels use public model identifiers from `/v1/models`: alias names or `connectionId/modelId`. Empty list means all enabled targets.

Internal POST `/v1/router/generate` body `{connectionId?,providerId?,modelId?,aliasId?,messages:[{role:'user',content:prompt}],stream:true,max_tokens:256}`. A provider/model selection uses configured account order and optional round robin. External POST `/v1/chat/completions` accepts OpenAI Chat body with `model` alias name or `connectionId/modelId`. Both use the same router pipeline. Streaming is OpenAI SSE (`data: {JSON}\n\n`, then `[DONE]`). Initial chunk includes `boxfox:{requestId,connectionId,modelId,aliasId}`; subsequent chunks contain choices[].delta.content/tool_calls/reasoning_content, terminal finish_reason, final usage if available. Deltas that carry only reasoning (`reasoning_content` or `reasoning`) are forwarded, not dropped; the non-stream response reports the accumulated text as `reasoning_content` when there is any. SSE errors are `{error:{code,message,retryable},boxfox:{...}}`, no DONE success after failure. Stop aborts fetch, server cancels upstream. Nonstream returns standard OpenAI response plus boxfox and actual usage.

Anthropic Messages ingress: POST `/v1/messages` accepts an Anthropic Messages body (`model`, `system` as string or text blocks, `messages` with `text`/`image`/`tool_use`/`tool_result` blocks, `tools[].input_schema`, `tool_choice`, `max_tokens` 1–64000, `stream`) and answers in Anthropic's own SSE dialect: `event: <type>\ndata: <JSON>\n\n` frames, `message_start` → `content_block_start`/`content_block_delta`/`content_block_stop` per block → `message_delta` → `message_stop`, and never `[DONE]`. POST `/v1/messages/count_tokens` returns `{input_tokens}` and never calls a provider; it estimates `ceil(chars/4)` over `system`, `tools` and messages (image payloads are not counted). Both routes authenticate with `x-api-key` or `Authorization: Bearer` against the same gateway-key store as `/v1/chat/completions` (Bearer is checked first, then `x-api-key`), and both refuse a model the key may not use before any provider call. `model` follows the same rule as every other route: alias name or `connectionId/modelId` — the router never infers a provider from a bare Anthropic model name such as `claude-sonnet-4-5`. Anthropic-only fields with no OpenAI-side equivalent (`top_k`, `metadata`, `mcp_servers`, `context_management`, …) are dropped, `thinking {type:'enabled',budget_tokens}` becomes the model's own `thinkingLevel` (≤4096 low, ≤12288 medium, else high), and a content block or image source the router cannot represent is a 400 instead of a silent drop. Errors are `{type:'error',error:{type,message}}` with the Anthropic error type for the router code (`authentication_error`, `permission_error`, `not_found_error`, `rate_limit_error`, `invalid_request_error`, `api_error`); a failure after the first frame arrives as an `event: error` frame and the stream ends without `message_stop`. Requests that carry a `claude-cli` user-agent are answered locally for Claude Code's housekeeping traffic (warm-up, its `{"title":…}` turn, title-instruction and topic-naming prompts) — only when the request has no tools — so those calls never reach a provider. Gemini-backed providers require their opaque `thought_signature` on a replayed tool call; the ingress remembers it per tool call id and re-attaches it on the `tool_result` round trip, because an Anthropic `tool_use` block has nowhere to carry it.

Model record (returned by `discover`, by `connections[].models` in `/api/router/state`, and by `/v1/models`): `{id,name,source,contextWindow,thinkingType,defaultThinking,thinkingLevels,stale,enabled,capabilities,...}` where `contextWindow` is a token count or `null`, `thinkingType` is `'effort'|'budget'|'fixed'|'none'` and `defaultThinking` is the level the provider publishes or `null`. These fields come only from provider payloads or documented provider rules — never from model-name patterns; when a payload does not say, the record is `contextWindow:null`, `thinkingType:'none'`, `defaultThinking:null`, `thinkingLevels:[]`. A curated catalog that is not a live inventory is labelled `source:'static'`. The router translates the level per adapter on the wire: `effort` => `reasoning_effort` (OpenAI-compatible) or `thinkingLevel` (Gemini/Antigravity), `budget` => Anthropic `thinking.budget_tokens` (low/medium/high => 2048/8192/16384), and no thinking field is sent for `none`/`fixed` or when the model reports no thinking control.

Provider adapter interface (worker-owned `src/providers/index.mjs`): `createProviders({fetchImpl})` returns registry; each adapter has `discover({connection,credentials,signal})` => `{models,email?,projectId?,projectState?,credentials?}`, `generate({connection,credentials,body,signal})` async generator yielding `{type:'delta',delta:{content?,tool_calls?,role?}} | {type:'finish',finishReason:string} | {type:'usage',usage:{prompt_tokens?,input_tokens?,completion_tokens?,output_tokens?,total_tokens?,cached_tokens?,cache_read_input_tokens?,cache_creation_input_tokens?,reasoning_tokens?,cost?}}`; BoxFox normalizes prompt/input, cache-read/write, reasoning and total tokens before recording usage. Cost stays null unless a provider reports a trusted value or pricing is explicitly integrated. `quota({connection,credentials,signal})` => ProviderQuota. Antigravity additionally `oauthConfig`, `buildAuthUrl({redirectUri,state})`, `exchangeCode({code,redirectUri,signal})`, `refresh({credentials,signal})`. Credential shape `{apiKey?} | {accessToken,refreshToken?,expiresAt,projectId?,oauthClient:{clientId,clientSecret?},email?}`; refresh preserves issuer binding. Provider errors throw `{code,status,retryable,message}` via exported error helper or compatible Error. fetchImpl is an injected policy-enforcing fetch; no raw console credential/payload logging. Account/store persistence belongs to main worker.
